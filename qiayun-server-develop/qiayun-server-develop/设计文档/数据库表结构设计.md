# HiMorning应用数据库表结构设计

## 📊 数据库设计概览

### 设计原则
- **规范化设计：** 遵循第三范式，减少数据冗余
- **性能优化：** 合理建立索引，优化查询性能
- **扩展性：** 预留扩展字段，支持业务发展
- **数据完整性：** 外键约束，保证数据一致性

### 技术栈
- **数据库：** MySQL 8.0
- **ORM：** Prisma 5.x
- **字符集：** utf8mb4 (支持emoji)
- **存储引擎：** InnoDB

## 🗂️ 表结构设计

### 1. 用户相关表

#### users (用户基础信息表)
```sql
CREATE TABLE users (
  id            INT PRIMARY KEY AUTO_INCREMENT,
  phone         VARCHAR(20) UNIQUE NULL COMMENT '手机号',
  wechat_openid VARCHAR(100) UNIQUE NULL COMMENT '微信OpenID',
  wechat_unionid VARCHAR(100) UNIQUE NULL COMMENT '微信UnionID',
  nickname      VARCHAR(50) NOT NULL COMMENT '用户昵称',
  avatar_url    VARCHAR(500) NULL COMMENT '头像URL',
  gender        ENUM('MALE', 'FEMALE', 'UNKNOWN') DEFAULT 'UNKNOWN' COMMENT '性别',
  birth_date    DATE NULL COMMENT '生日',
  city          VARCHAR(50) NULL COMMENT '城市',
  bio           VARCHAR(200) NULL COMMENT '个人简介',
  theme         VARCHAR(20) DEFAULT 'sunrise' COMMENT '主题偏好',
  language      VARCHAR(10) DEFAULT 'zh-CN' COMMENT '语言偏好',
  timezone      VARCHAR(50) DEFAULT 'Asia/Shanghai' COMMENT '时区',
  status        ENUM('ACTIVE', 'INACTIVE', 'BANNED') DEFAULT 'ACTIVE' COMMENT '用户状态',
  last_login_at DATETIME NULL COMMENT '最后登录时间',
  created_at    DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  updated_at    DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  
  INDEX idx_phone (phone),
  INDEX idx_wechat_openid (wechat_openid),
  INDEX idx_status (status),
  INDEX idx_created_at (created_at)
) COMMENT '用户基础信息表';
```

#### user_profiles (用户扩展信息表)
```sql
CREATE TABLE user_profiles (
  id                    INT PRIMARY KEY AUTO_INCREMENT,
  user_id               INT NOT NULL COMMENT '用户ID',
  total_checkin_days    INT DEFAULT 0 COMMENT '总打卡天数',
  continuous_days       INT DEFAULT 0 COMMENT '连续打卡天数',
  max_continuous_days   INT DEFAULT 0 COMMENT '最大连续打卡天数',
  total_points          INT DEFAULT 0 COMMENT '总积分',
  level                 INT DEFAULT 1 COMMENT '用户等级',
  preferred_categories  JSON NULL COMMENT '偏好内容分类',
  notification_settings JSON NULL COMMENT '通知设置',
  privacy_settings      JSON NULL COMMENT '隐私设置',
  created_at           DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at           DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  UNIQUE KEY uk_user_id (user_id),
  INDEX idx_total_checkin_days (total_checkin_days),
  INDEX idx_continuous_days (continuous_days)
) COMMENT '用户扩展信息表';
```

#### user_tokens (用户令牌表)
```sql
CREATE TABLE user_tokens (
  id           INT PRIMARY KEY AUTO_INCREMENT,
  user_id      INT NOT NULL COMMENT '用户ID',
  token_type   ENUM('ACCESS', 'REFRESH') NOT NULL COMMENT '令牌类型',
  token_hash   VARCHAR(255) NOT NULL COMMENT '令牌哈希',
  expires_at   DATETIME NOT NULL COMMENT '过期时间',
  is_revoked   BOOLEAN DEFAULT FALSE COMMENT '是否已撤销',
  device_info  JSON NULL COMMENT '设备信息',
  created_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
  
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  INDEX idx_user_token (user_id, token_type),
  INDEX idx_expires_at (expires_at),
  INDEX idx_token_hash (token_hash)
) COMMENT '用户令牌表';
```

### 2. 打卡相关表

#### checkins (打卡记录表)
```sql
CREATE TABLE checkins (
  id          INT PRIMARY KEY AUTO_INCREMENT,
  user_id     INT NOT NULL COMMENT '用户ID',
  type        ENUM('MORNING', 'EVENING') NOT NULL COMMENT '打卡类型',
  content     TEXT NULL COMMENT '心语内容',
  mood        ENUM('HAPPY', 'CALM', 'TIRED', 'EXCITED', 'THOUGHTFUL', 'GRATEFUL', 'SAD', 'ANXIOUS') NOT NULL COMMENT '心情状态',
  weather     VARCHAR(20) NULL COMMENT '天气',
  location    VARCHAR(100) NULL COMMENT '位置',
  is_public   BOOLEAN DEFAULT TRUE COMMENT '是否公开',
  checkin_date DATE NOT NULL COMMENT '打卡日期',
  checkin_time TIME NOT NULL COMMENT '打卡时间',
  created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at  DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  UNIQUE KEY uk_user_date_type (user_id, checkin_date, type),
  INDEX idx_user_date (user_id, checkin_date DESC),
  INDEX idx_mood (mood),
  INDEX idx_type (type),
  INDEX idx_public (is_public)
) COMMENT '打卡记录表';
```

#### checkin_images (打卡图片表)
```sql
CREATE TABLE checkin_images (
  id         INT PRIMARY KEY AUTO_INCREMENT,
  checkin_id INT NOT NULL COMMENT '打卡记录ID',
  image_url  VARCHAR(500) NOT NULL COMMENT '图片URL',
  thumbnail_url VARCHAR(500) NULL COMMENT '缩略图URL',
  width      INT NULL COMMENT '图片宽度',
  height     INT NULL COMMENT '图片高度',
  file_size  INT NULL COMMENT '文件大小(字节)',
  sort_order INT DEFAULT 0 COMMENT '排序',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  
  FOREIGN KEY (checkin_id) REFERENCES checkins(id) ON DELETE CASCADE,
  INDEX idx_checkin_id (checkin_id),
  INDEX idx_sort_order (sort_order)
) COMMENT '打卡图片表';
```

#### checkin_stats (打卡统计表)
```sql
CREATE TABLE checkin_stats (
  id                    INT PRIMARY KEY AUTO_INCREMENT,
  user_id               INT NOT NULL COMMENT '用户ID',
  stat_date             DATE NOT NULL COMMENT '统计日期',
  morning_checkin       BOOLEAN DEFAULT FALSE COMMENT '早晨是否打卡',
  evening_checkin       BOOLEAN DEFAULT FALSE COMMENT '晚上是否打卡',
  daily_completed       BOOLEAN DEFAULT FALSE COMMENT '当日是否完成',
  continuous_days       INT DEFAULT 0 COMMENT '连续天数',
  week_completed_days   INT DEFAULT 0 COMMENT '本周完成天数',
  month_completed_days  INT DEFAULT 0 COMMENT '本月完成天数',
  created_at           DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at           DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
```


#### contents (内容表)
```sql
CREATE TABLE contents (
  id            INT PRIMARY KEY AUTO_INCREMENT,
  category_id   INT NOT NULL COMMENT '分类ID',
  title         VARCHAR(200) NOT NULL COMMENT '标题',
```

#### user_content_interactions (用户内容交互表)
```sql
CREATE TABLE user_content_interactions (
  id          INT PRIMARY KEY AUTO_INCREMENT,
  user_id     INT NOT NULL COMMENT '用户ID',
  content_id  INT NOT NULL COMMENT '内容ID',
  action_type ENUM('VIEW', 'LIKE', 'SHARE', 'FAVORITE') NOT NULL COMMENT '交互类型',
```

## 📈 索引优化策略

### 主要索引设计

#### 1. 用户相关索引
```sql
-- 用户表
CREATE INDEX idx_users_phone ON users(phone);
CREATE INDEX idx_users_wechat_openid ON users(wechat_openid);
CREATE INDEX idx_users_status_created ON users(status, created_at DESC);

-- 用户档案表
CREATE INDEX idx_profiles_checkin_stats ON user_profiles(total_checkin_days DESC, continuous_days DESC);
```

#### 2. 打卡相关索引
```sql
-- 打卡记录表
CREATE INDEX idx_checkins_user_date_type ON checkins(user_id, checkin_date DESC, type);
CREATE INDEX idx_checkins_mood_date ON checkins(mood, checkin_date DESC);
CREATE INDEX idx_checkins_public_date ON checkins(is_public, checkin_date DESC);

-- 打卡统计表
CREATE INDEX idx_stats_user_continuous ON checkin_stats(user_id, continuous_days DESC);
```

#### 3. 内容相关索引
```sql
-- 内容表
CREATE INDEX idx_contents_category_published ON contents(category_id, published_at DESC);
CREATE INDEX idx_contents_featured_published ON contents(is_featured, published_at DESC);
CREATE INDEX idx_contents_view_count ON contents(view_count DESC);

-- 全文搜索索引
CREATE FULLTEXT INDEX idx_contents_search ON contents(title, summary);
```

## 🔄 数据迁移策略

### 版本控制
- 使用Prisma Migrate管理数据库版本
- 每个功能迭代对应一个迁移文件
- 生产环境迁移需要审批流程

### 数据备份
- 迁移前自动创建数据库备份
- 支持迁移回滚机制
- 关键数据变更需要人工确认

### 性能考虑
- 大表结构变更分批执行
- 避免在业务高峰期执行迁移
- 监控迁移过程中的性能影响

---

**设计说明：**
- 所有表都包含创建时间和更新时间字段
- 使用外键约束保证数据完整性
- JSON字段存储灵活的配置信息
- 合理的索引设计优化查询性能
- 支持软删除和逻辑删除策略
